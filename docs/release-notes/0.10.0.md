**New**

- **Attach a disk as a raw device, for virtual machines.** In Discover, the Add button has a pull-down with **Add as a Raw Device**. For a saved target, turn on **Attach as a raw device** in its settings. The disk is then attached with nothing on it mounted, as `/dev/rdiskN`, which a virtual machine running in your account can use as its disk. A VM disk kept as an image file on an attached APFS volume can stall for many seconds at a time; on the raw device it doesn't. The README's [Virtual machines](https://github.com/MacFabric/iSCSI-NVMe-TCP#virtual-machines) section has more.
- **The Sessions pane says how each disk is attached:** as volumes or as a raw device, through which attach engine, and as which device.
- **Spanish and Simplified Chinese.** The app follows your Mac's language. Thanks to @Lxy521031 for the Chinese translation (#15).
- **Encrypted volumes.** A disk whose APFS volume is encrypted and locked is now described as encrypted, instead of "not formatted" with advice to erase it. If macOS saved the volume's password in your keychain, the app unlocks it when it attaches the disk.
- Until you add your first target, Discover comes first in the sidebar.

**Faster**

- NVMe/TCP and iSCSI use less processor time per byte: faster checksums, and reads and sends that skip a copy. In one measurement, raw NVMe/TCP reads used about a third less CPU at the same speed.
- The read cache, and the encrypted local disk cache, do less work for each read and write.

**Fixes**

- A target that stalls for up to about a minute and a half no longer fails a file copy partway through. Reads and writes now wait out the background service's own reconnect and retry.
- If a write is never answered, the volume now stops instead of carrying on, because that write could still land later on top of newer data.
- A connection to a target is no longer left open when the app loses touch with the background service mid-attach, or when you detach while the connection is being restored.
- An update is no longer installed under attached volumes. Quitting with an update ready asks you to detach first.

**Known issue**

- One report (#16) describes a disk holding an APFS volume that read as blank after it was detached and attached again, with the app suggesting an erase. It has not been reproduced. If a disk you know holds data is ever called "not formatted", don't erase it, and please add what you see to #16.

**Upgrading**

- After the update, Setup asks you to **Reinstall** the background service. On macOS 26, you may need to click **Enable** again as well.
- Saved targets and passwords carry over unchanged.
